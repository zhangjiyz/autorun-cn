# 启动器更新

**设置 → 系统 → 检查更新**会读取 CNB `PalmMuse/autorun-cn` 最新的正式 Release。启动时的后台检查只显示通知；安装更新始终需要确认。正式版先排除与构建标签或已安装标签相同的 Release；旧版手动安装包若没有这两种标签，还会比对 NACP 版本。只有版本不同且 Release 发布时间晚于源码提交时间时才提示更新。
手动检查若没有更新，会直接提示“已是最新”并返回设置页；只有发现新版本时才显示更新说明和安装入口。

**设置 → 系统 → Autorun 版本**显示当前主程序版本，优先使用构建时编入的 Release 标签；没有该标签时，使用经 NRO 校验的在线安装记录，最后回退到 NACP 版本。

正式发布包构建时需指定将要发布的标签，并编入 NRO。这样手动安装同一 Release 包后，不会再次提示安装它。Debug 构建读取固定测试标签，允许手动重装同标签包。

启动器会校验发布文件的 SHA-256 摘要，然后解压完整的 `switch/wine` 压缩包。路径重叠时，现有配置、游戏文件、存档、封面和已下载的图形组件版本会保留。安装包中的运行环境 DLL、字体、NLS 数据、捆绑的图形 DLL、许可证和主 NRO 会被替换。新版本中的新增文件和目录也会被安装。

请在 SD 卡上预留下载、解压及备份所需的空间。开始替换文件前可以取消安装。替换与重启期间请保持主机通电。AMD64 构建会拒绝缺少 AMD64 运行环境的安装包。

安装中断时，程序会在 Wine 加载 DLL 前回滚。备份保存在 `switch/wine/updates` 下，直到更新后的启动器成功打开。如果断电导致主 NRO 无法启动，请从自制程序菜单打开 `switch/wine/updates/previous.nro`，恢复之前的安装。恢复未完成时请勿删除更新目录。

Switch 构建除了现有的 curl 和 zlib 依赖，还需要 devkitPro 的 `switch-minizip`。构建时会从 Git 写入版本标识。缺少 Git 元数据的构建可以显示发布版本，但不会猜测某个发布版本是否更新。
